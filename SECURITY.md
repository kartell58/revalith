# Security Policy

## Scope of this repository

This repository contains **documentation and analysis tooling only**:

- Markdown methodology, reference material and worked examples
- Dependency-free Python 3 CLIs that *read* binaries

Nothing here executes a target program, exploits a vulnerability, accesses
credentials, or modifies third-party systems.

## What the scripts do

Every script is read-only with respect to its input file. They open binaries
for reading, parse structures, and print results. They do not patch, inject,
write to, or execute the files they inspect.

`patchelf` and debugger tooling appear in the documentation as *things an
analyst may use*. They are not invoked by any script in this repository.

## Acceptable use

The skill is intended for:

- Understanding software you own, are licensed to analyse, or have permission
  to test
- Debugging, interoperability and compatibility research
- Vulnerability research and defensive security analysis
- Reverse engineering for interoperability, archival or education

## Unacceptable use

- Attacking systems you do not own or have written authorisation to test
- Malware development or deployment
- Credential theft, ransomware, or evasion for malicious purposes
- Bypassing access controls or licensing enforcement without authorisation

## A note on legal and ethical boundaries

Analysing a binary you own, or one covered by an explicit exemption such as
interoperability research, is generally lawful. Reverse engineering for
circumventing licence enforcement or access controls may not be, depending on
jurisdiction. **This repository cannot provide legal advice, and its
documentation is not legal advice.**

If you are unsure whether a specific activity is permitted, check your
applicable law, your licence agreement, and your employment contract — or ask
qualified counsel — before proceeding.

## Reporting a vulnerability

This repository has no running service and accepts no untrusted input, so
there is no meaningful attack surface. Security issues in the sense of
remotely exploitable vulnerabilities do not apply.

What *is* worth reporting is a correctness or safety defect in the tooling:

- A script that modifies the file it was asked to inspect
- A parser that reads out of bounds or mishandles a malformed input
- An example that encourages an unsafe or legally problematic technique

Report these as a GitHub issue, or contact the maintainer directly at
**ryanpabloha@gmail.com**. Expect a best-effort response.

## Handling binaries

If you contribute a binary fixture, make sure it is either:

- Synthetic, generated by code in this repository, or
- A build you have the right to redistribute

Never commit proprietary binaries, licensed SDKs, or anything extracted from a
third-party installation. `.gitignore` already excludes `*.pcap` and capture
directories to reduce the chance of accidental inclusion.
