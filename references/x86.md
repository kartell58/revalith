# x86 and x86-64

Enough to recover control flow, calls, arguments and data access for the
architectures most often encountered on desktops and servers.

## Registers

**x86-64 (System V):**

| Purpose | Registers |
| --- | --- |
| Integer args 1–6 | `rdi`, `rsi`, `rdx`, `rcx`, `r8`, `r9` |
| Return value | `rax` |
| Callee-saved | `rbx`, `rbp`, `r12`–`r15` |
| Frame pointer | `rbp` |
| Stack pointer | `rsp` |
| Scratch | `r10`, `r11` |
| Float args 1–8 | `xmm0`–`xmm7` |

Integer args go in `rdi`, `rsi`, `rdx`, `rcx`, `r8`, `r9` — note `rcx`, not
`rcx`-adjacent like ARM. Floating-point arguments are separate: an
instruction with `xmm` operands is not an integer argument.

Stack alignment is 16 bytes at call sites.

**Windows x64** differs: `rcx`, `rdx`, `r8`, `r9` for the first four
arguments, everything else on the stack, and `xmm0`–`xmm3` for the first four
floats.

**32-bit x86 (cdecl):** all arguments on the stack; `eax` returns. Stack
cleanup by the caller. `callee`-saved: `ebx`, `esi`, `edi`, `ebp`.

## Instruction set that matters

### Calls and control flow

| Instruction | Effect |
| --- | --- |
| `call <rel32>` | direct call, pushes return address |
| `call qword ptr [rip+disp]` | indirect call through memory |
| `call rax` | indirect call through a register |
| `jmp <rel32>` / `jmp rax` | jump |
| `ret` | return, pops return address |
| `ret imm16` | return and pop extra bytes (callee cleanup) |
| `jmp qword ptr [rip+disp]` | tail call / jump-table dispatch |
| `int3` | breakpoint trap / padding |

`ret imm16` is a strong cdecl or stdcall indicator; cdecl has a bare `ret`.

### Addressing

x86-64 reaches data RIP-relatively:

```
lea  rax, [rip + 0x1234]     ; rax = address (no memory access)
mov  rax, [rip + 0x1234]     ; load 8 bytes from that address
```

`lea` computes an address without loading; using `lea` on a string address
and then passing the pointer is extremely common. Because the displacement is
relative to the *next* instruction, static address extraction needs the
instruction's own address plus its length.

32-bit x86 uses absolute or `ebx`-relative addressing, often via a global
offset table when position-independent code is wanted.

### Comparing and branching

| Instruction | Effect |
| --- | --- |
| `cmp`, `test` | set flags |
| `setcc` | set a byte from flags |
| `cmovcc` | conditional move (branchless select) |
| `jcc` | conditional jump |
| `test reg, reg` followed by `jz` | common null/zero check |

`cmovcc` expresses an if/else without branching. As on ARM, reading only
explicit jumps misses the real structure.

### Stack frames

```
push rbp
mov  rbp, rsp
sub  rsp, 0x20
...
mov  rsp, rbp
pop  rbp
ret
```

Omit-frame-pointer builds skip the first two instructions, so `rbp` is a
general register and cannot be used to walk frames.

`leave` is `mov rsp, rbp; pop rbp`.

## Recognising common idioms

```asm
xor  eax, eax          ; return 0 / NULL
ret

mov  rax, qword ptr [rdi + 0x10]   ; load field at offset 0x10
mov  ecx, dword ptr [rsi + 8]      ; load 32-bit field at offset 8
lea  rdx, [rdi + 0x20]             ; address of field at 0x20

call qword ptr [rax + 0x28]        ; virtual call: vtable slot at 0x28
```

Struct offsets show up directly in displacement values. A consistent set of
`[reg+N]` offsets across a group of functions is how a structure is
recovered — see the struct workflow in `methodology.md`.

## Indirect calls and vtables

```
mov  rax, [rdi]              ; vtable pointer (first field of the object)
call qword ptr [rax + 0x28]  ; virtual method at slot 0x28
```

Slot offset divided by 8 gives the method index. To enumerate a class's
methods, find the vtable in `.data.rel.ro`, read consecutive slots, and
resolve each one. If the object pointer comes from a different register than
the call target base, the register flow tells you which field holds it.

Jump tables look like `jmp qword ptr [rax*8 + table_base]`; the table lives
in `.rodata` and contains code addresses.

## Reading a function

1. Look for the `push rbp; mov rbp, rsp` prologue and frame size.
2. Identify reads of `rdi`, `rsi`, `rdx`, `rcx`, `r8`, `r9` before any write.
3. Collect `call` targets — including `call [rip+disp]`, which means an
   import; resolve the IAT slot to a name.
4. Note `[reg+disp]` patterns: these are structure field accesses.
5. Check `eax`/`rax` before each `ret`.
6. `jmp` to another function at the end means tail call, not a return.

## Interop notes

- Distinguish 32-bit from 64-bit before assuming a calling convention.
- `ptr` in a disassembly comment means a dereference; the disassembly already
  resolved it for you.
- Endbr64/Endbr32 at function starts are CET/IBT landing pads. They are
  architectural noise, not logic.
- Intel CET introduces shadow stacks; a `ret` may not return where the
  disassembly's control flow suggests.
- `syscall` and `int 0x80` are direct kernel transitions; a lot of behaviour
  can live there rather than in the function itself.
- Packed or obfuscated x86 frequently uses self-modifying code, which makes
  static disassembly of the on-disk bytes misleading.
